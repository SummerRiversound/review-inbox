# Review Inbox

[English](README.md) | [한국어](README.ko.md) | **日本語** | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [Español](README.es.md) | [Português](README.pt-BR.md) | [Deutsch](README.de.md) | [Français](README.fr.md)

コーディング中も GitHub での自分の作業を見失わないための [Claude Code](https://claude.com/claude-code) の mod です。自分のレビューを待っているプルリクエスト（それぞれ開く前にわかりやすい言葉で要約します）、オープン中の自分の PR とそれに付いたレビュー、そして自分に声がかかった Issue を表示します。

- **入力欄の上の帯** — 自分の対応が必要なものだけを数える1行です。自分のレビューを待っている PR、要対応の自分の PR、自分に割り当てられた Issue や自分がメンションされた Issue を数えます。色は、最も長く待っているレビューリクエストの待ち日数を表します（3日から黄色、14日から赤）。`開く` でドロワーが開きます。
- **ドロワー** — `/review-inbox` で開く「レビュー受信トレイ」です。「要レビュー」「自分の PR」「自分の Issue」の3つのタブがあります。
- **トースト通知** — 作業中に新しい項目が届くと、短く知らせます。

![入力欄の上の帯と、ドロワーの3つのタブ（要レビュー、自分の PR、自分の Issue）](docs/images/en/overview.gif)

画面表示と要約は9つの言語に対応しています。詳しくは [言語](#言語) をご覧ください。

## タブ

### 要レビュー

自分のレビューを待っている PR ごとに、カードを1枚表示します。カードには1文の概要、PR の目的、影響範囲、変更規模と作成者、レビュー待ちの経過日数が載ります。スキーマ変更や必須のデプロイ順序など、リスクのある項目には ⚠️ が付きます。

- `レビューする` を押すとカードが `追加済み` になり、ドロワーは開いたままなので、複数の PR を選べます。ドロワーを閉じると（Esc または ×）、追加した PR ごとのレビュー依頼が、注意点と前回の自分のレビュー以降の変更点とともに入力欄に入ります。Enter を押すまで何も送信されません。入力欄の下書きですでに依頼している PR は、ドロワーを開いたときに `追加済み` と表示されます。
- `非表示` を押すと、その PR に新しいコミットが追加されるまでカードを隠します。
- `再リクエスト` は、レビュー済みの PR からもう一度レビューを求められたことを示します。前回の自分のレビュー以降の変更点を短くまとめて表示します。
- 直接リクエストはチームへのリクエストより先に表示します。ドラフトは別にまとめて表示します。

![2枚のカードで「レビューする」を押すと「追加済み」になり、3枚目は「非表示」で隠れ、Esc で2件のレビュー依頼が入力欄に入る様子](docs/images/en/review.gif)

レビュー依頼には、普段の自分のレビュースタイルを説明する1行も付くので、Claude は自分と同じやり方でレビューします。mod は週に1回、最近レビューした PR（最大30件）に自分が残したコメントを読み、使う言語と口調、最初に見るところ、依頼の言い回しを Claude にまとめてもらいます。学習に使えるコメントが5件未満の場合、その1行を付けずに依頼します。学習に失敗した場合は前回の説明をそのまま使い、1日後に再試行します。

### 自分の PR

オープン中の自分の PR を、概要の代わりに状態とともに、対応すべき順に表示します。並び順は、変更リクエスト、CI 失敗、マージコンフリクト、レビュー待ち（古いものから）、承認済み、ドラフトです。実行中の CI は状態の横に表示します。

![自分の PR タブ: 変更リクエストからドラフトまでの6件の PR。うち2件に新しいレビュー](docs/images/en/my-prs.png)

最新のコミットより後に提出されたレビューは、レビューした人とともに `新しいレビュー` と表示され、次にコミットするまで残ります。承認、変更リクエスト、コメントのみのレビューが対象で、スレッドへの返信も含み、人とボットのどちらからのものも数えます。却下（dismiss）されたレビューは数えません。こうした PR は要対応として数え、同じ状態の中で動きのない PR より前に並びます。モデルの呼び出しはありません。

### 自分の Issue

自分に割り当てられたオープンな Issue と、自分がメンションされたオープンな Issue・PR を表示します。両方に当てはまる項目は「自分に割り当て」として1回だけ表示します。その下には、過去30日間に自分の Issue や PR を参照した他の Issue・PR を、参照した人とともに表示します。自分自身による参照は除き、新しいものから20件だけを表示します。モデルの呼び出しはありません。

![自分の Issue タブ: 割り当てられた Issue、メンション、他の場所からの自分の作業への参照](docs/images/en/my-issues.png)

### トースト通知

新しいレビューリクエスト、自分の PR への新しいレビュー、自分の PR が変更リクエスト・CI 失敗・マージコンフリクトの状態になったとき、そして新しい割り当て・メンション・参照があったときに通知します。セッションが最初に一覧を読み込んだときは何も通知しません。同時に複数届いた場合は、4.5秒間隔で1件ずつ表示します。

![入力欄の下に3つのトースト通知が順に表示される様子: 新しいレビューリクエスト、自分の PR への変更リクエスト、新しいメンション](docs/images/en/toasts.gif)

## 動作要件

- Claude Code 2.1.287 以降。mod（function-hook プラグイン）に対応した最初のビルドです。2.1.292 で動作を確認しています。mod はアーリーアクセス段階のため、リリース間で API が変わる可能性があります。
- [GitHub CLI](https://cli.github.com/)（`gh`）が `PATH` 上にあり、レビュー対象のリポジトリにアクセスできるアカウントでログイン済み（`gh auth login`）であること。
- GitHub Enterprise Server の場合: Claude Code を起動する環境で `GH_HOST` を設定してください。すべての `gh` 呼び出しがそのホストに送られます。

## インストール

Claude Code セッションの入力欄で次を実行します。

```text
/plugin marketplace add https://github.com/SummerRiversound/review-inbox.git
/plugin install review-inbox@review-inbox
```

インストール画面で以下のオプションを尋ねられます。いずれも空欄またはデフォルト値のままでかまいません。

### アップデートとアンインストール

```sh
claude plugin marketplace update review-inbox
claude plugin update review-inbox@review-inbox
claude plugin uninstall review-inbox@review-inbox
```

アップデートは再起動後に反映されます。アンインストールしても mod のキャッシュフォルダ `~/.claude/plugins/data/review-inbox` は残ります。キャッシュされた一覧と要約も消すには、このフォルダを手動で削除してください。各バージョンの変更内容は [変更履歴](CHANGELOG.md) をご覧ください。

## 設定

インストール画面で設定し、後から `/config` で変更できます。変更はすぐに反映されます。

| オプション | デフォルト | 内容 |
| --- | --- | --- |
| `scope` | 空 | すべての検索（`review-requested:@me`、`author:@me`、`assignee:@me`、`mentions:@me`）に追加する GitHub の検索修飾子です。空の場合は GitHub 全体が対象です。 |
| `githubUser` | 空 | 複数のアカウントでログインしているときに使う `gh` アカウントです（`gh auth token -u <user>`）。空の場合はアクティブなアカウントを使います。 |
| `language` | `auto` | `auto`、または [言語](#言語) にあるコードのいずれかです。 |

`scope` には、GitHub の [Issue と PR の検索](https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests) で使えるものなら何でも指定できます。

```text
org:my-org
org:my-org org:other-org
repo:owner/name repo:owner/other
org:my-org -repo:my-org/noisy-repo
user:my-username
```

`org:`、`repo:`、`user:` の修飾子を複数指定すると、そのいずれかに一致するものが対象になります。チームへのレビューリクエストも、GitHub の `review-requested:@me` の定義どおり、自分へのリクエストとして数えます。

## 言語

帯、ドロワー、トースト通知、入力欄に入るレビュー依頼、そしてモデルが書く要約とレビュースタイルの説明は、すべて同じ1つの言語で表示されます。

| コード | 言語 |
| --- | --- |
| `en` | 英語（English） |
| `ko` | 韓国語（한국어） |
| `ja` | 日本語 |
| `zh-CN` | 簡体字中国語（简体中文） |
| `zh-TW` | 繁体字中国語（繁體中文） |
| `es` | スペイン語（Español） |
| `pt-BR` | ブラジルポルトガル語（Português do Brasil） |
| `de` | ドイツ語（Deutsch） |
| `fr` | フランス語（Français） |

- コードを指定すると、その言語になります。
- `auto`（デフォルト）は、Claude Code 自体の `language` 設定がこれらの言語のいずれかを指していれば、それに従います。コード、英語名、その言語自身での名前のいずれでも認識します（`ja-JP`、`Japanese`、`日本語`）。そうでなければシステムのロケール（`LC_ALL`、`LC_MESSAGES`、`LANG` の順）に従い、それもなければ英語になります。中国語は、台湾・香港・マカオまたは繁体字の指定（`zh-TW`、`zh-Hant`、`繁體中文`）がない限り簡体字として扱い、ポルトガル語はブラジルポルトガル語として扱います。

要約とレビュースタイルの説明は言語ごとにキャッシュされるため、言語を切り替えると、それぞれの要約とその説明を新しい言語でもう一度作成します。上記以外の言語は英語にフォールバックします。

英語と韓国語以外の言語は Claude で翻訳したもので、まだネイティブスピーカーによる確認を受けていません。この README も同じ方法で翻訳しています。修正は Issue またはプルリクエストで歓迎します。各言語は [`hooks/locales/`](hooks/locales/) 内の1ファイルで、他のすべての言語の基準となる英語の表は [`hooks/i18n.ts`](hooks/i18n.ts) にあります。

## 読み取るものと実行するもの

この mod は、自分の `gh` を通してのみ GitHub にアクセスします。要約を作成するために PR のテキストを、レビュースタイルを説明するために週に1回自分のレビューコメントを Claude に送り、ファイルは自身のキャッシュフォルダにのみ書き込みます。以下は、mod がアクセスするものとその理由の一覧で、`claude plugin validate .` がこの mod について表示する内容と一致します。

- **`gh` の実行**: 一覧の取得と、週に1回の最近のレビューコメントの取得に `gh api graphql` を、再リクエストされた PR には `gh api repos/<owner>/<repo>/compare/<from>...<to>` を、`githubUser` が設定されている場合は `gh auth token -u <githubUser>` を実行します。mod 自身がこれ以外のネットワーク呼び出しを行うことはありません。
- **Claude への依頼**（`sonnet` モデル）: 要約ごとに、PR のリポジトリ名、タイトル、説明（先頭12,000文字）、変更されたファイルのパス（最大80件）、変更規模を送ります。再リクエストされた PR では、前回の自分のレビュー以降の各コミットメッセージの1行目と、最大60件のファイルパスも送ります。これは Claude Code の使用量に含まれます。各 PR の要約は head コミットと言語の組み合わせごとに1回作成し、要約に失敗した場合の試行はコミットごとに最大3回までです。また週に1回、レビュースタイルを説明するために、最近レビューした PR（最大30件）に自分が残したレビューコメントを送ります。コメントはそれぞれ500文字で切り詰め、最大60件、合計12,000文字までです。5件未満の場合は何も送りません。
- **ファイルの書き込み**: キャッシュフォルダ `~/.claude/plugins/data/review-inbox` の中にのみ書き込みます（`CLAUDE_CONFIG_DIR` が設定されている場合は `~/.claude` の代わりにそれを使います）。`inbox-<hash>.json` には一覧と要約、`hidden-<hash>.json` には非表示にした PR、`style-<hash>.json` にはレビュースタイルの説明を保存します。
- **環境変数の読み取り**: そのフォルダを見つけるために `CLAUDE_CONFIG_DIR`、`HOME`、`USERPROFILE` を読みます。`LC_ALL`、`LC_MESSAGES`、`LANG` は `language` が `auto` のときだけ読みます。環境変数を設定することはありません。
- **Claude Code の設定の読み取り**: `language` が `auto` のときだけ読み、使うのは `language` キーだけです。
- **入力欄の読み取りと入力**: ドロワーの開閉時だけ行います。ドロワーを開くときは、すでに依頼している PR に印を付けるために下書きを読み、閉じるときは、追加した PR の依頼を下書きの後ろに改行して追加します。

## 仕組み

開いているすべてのセッションが1回の取得結果を共有します。GitHub に問い合わせるのは1つのセッションだけで、その頻度は最大で10分に1回です。他のセッションは、そのセッションが保存した結果を読みます。

開いているすべての Claude Code セッションが mod を実行しますが、キャッシュファイルはアカウント・スコープ・言語の組み合わせごとに1つを共有し、非表示にした PR も同様です。各セッションは30秒ごとにこのファイルを読みます。ファイルが10分より古いことに気づき、短時間の取得権（claim）を獲得したセッションだけが GitHub を呼び出すため、10個のセッションを開いていてもリクエストは1回です。取得中のセッションは作業中に取得権を更新し続け、3分間更新されなかった取得権は他のセッションが引き継ぎます。取得に失敗した場合は最後に正常だった一覧を保持し、1分後に再試行します。ドロワーの `↻` を押すとすぐに取得します。

1回の GraphQL 検索で、自分のレビューを待っているすべての PR とカードに必要な情報を取得し、3つの検索をまとめたもう1回のリクエストで「自分の PR」と「自分の Issue」を埋めます。参照は、自分が作成した PR と Issue のクロスリファレンスイベントから取得します。GitHub は他の場所から参照されても項目の `updatedAt` を更新しないため、過去60日以内に更新された項目について、過去30日間の参照を1リクエストあたり50件ずつ確認します。GitHub が参照の検索を拒否した場合（クエリごとのリソース制限があります）、最後に取得した参照を保持し、他のタブは引き続き更新します。

## 制限事項

- 自分のレビューを待っている PR は、GitHub のベストマッチ順で最大100件です。他のタブでは、オープン中の自分の PR を最大100件、割り当てられた Issue を50件、メンションされた Issue を50件、最近更新された最大500件の項目からの参照を、それぞれ最新のアクティビティ順に読み込みます。
- 60日間更新されていない自分の項目への参照は検出されません。
- `新しいレビュー` は、PR に新しいコミットが追加されると消えます。GitHub の「Update branch」ボタンやボットによるコミットも含みます。
- レビューしたコミットが force-push で書き換えられた後は、再リクエストされた PR に「前回の自分のレビュー以降」の行が表示されません。
- レビュースタイルは、`scope` の範囲内で GitHub の検索が `reviewed-by:@me -author:@me` に対して返す PR から学習するため、自分が作成した PR に書いたコメントは含まれません。レビューの外で PR の会話に書いたコメントは含まれません。

## トラブルシューティング

- **ドロワーに `gh` のエラーが表示される。** `gh auth status` を実行してください。複数のアカウントでログインしている場合は `githubUser` を設定してください。mod は1分ごとに再試行します。
- **帯が表示されない。** 帯は自分の対応が必要なものがあるときだけ表示されます。0件の項目は表示されません。
- **期待した言語で表示されない。** `/config` で `language` を `auto` ではなく言語コードに設定してください。
- **その他の問題。** `claude --debug` で Claude Code を起動してください。この mod のログ行は `review-inbox:` で始まります。

## 開発

```sh
claude plugin validate .
claude plugin test .
claude --plugin-dir .
```

`claude plugin validate` と `claude plugin test` はログイン不要で、CI は動作確認済みの Claude Code ビルドでその両方を実行します。`tsconfig.json` は `.claude-plugin/types/tsconfig.json` を継承します。このファイルは Claude Code がこのフォルダから mod を初めて読み込むときに生成するもの（`.gitignore` で除外済み）なので、`tsc -p .` で型チェックする前に `claude --plugin-dir .` を一度実行してください。
